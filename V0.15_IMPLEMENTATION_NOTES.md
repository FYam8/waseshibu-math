# v0.15.0 GuidedSolution implementation notes

## Implemented
- 160/160 question IDs have static `GuidedSolution` records.
- Variable 2–4 STEP structure per question.
- 3-stage help: hint 1 → additional hint → STEP reveal.
- One-question-only review and full-answer reveal.
- Reproduction mode after closing guidance.
- Mastery states: unseen / attempted / exposed / guided / reproduced / independent / consolidated.
- Four consecutive practice answers are connected back to the source question when opened from GuidedSolution.
- Previous-question dependency mode: use own answer or official prior answer.
- Legacy `waseshibu-math-guided-review-v1` remains untouched.
- New progress is stored in `waseshibu-math-guided-progress-v2`.
- dataVersion 3 → 4 migration copies legacy Guided Review history non-destructively.
- Backup/export/restore includes the new progress key.
- App version bumped to 0.15.0.

## Data-preservation verification
The repository includes `scripts/test-migration-preservation.mjs`.
It creates an in-memory dataVersion 3 localStorage containing attempts, preferences, daily progress, exam scores, drafts, learning route, prep-check and Guided Review records; migrates without any export/import step; then verifies that every old learning-data value remains semantically identical while the new progress key is added.

Result in this workspace:
`PASS: エクスポートなしのv3 localStorageをv4へ非破壊移行し、全旧キーとGuided Review履歴を保持`

The self-check and migration-preservation test were each run twice consecutively and passed both times.

## Mathematical-content safety
The 160 GuidedSolution records are grounded in the existing per-question metadata/core ideas and official final-answer data. To avoid inventing unverified intermediate numerical claims, the first version of the per-question STEP content uses verified condition/method/checkpoint guidance and only exposes the official answer in the final explanation. This is safe for correctness, but some problems can still be improved further with hand-authored numerical intermediate steps from the original paper.

## Build verification
Core TypeScript modules (`dataMigration.ts`, `dataBackup.ts`, `guidedReview.ts` and dependencies) were compiled successfully in isolation. Full `npm run build` could not be completed in this sandbox because package installation was unavailable/incomplete; the failure was dependency availability (`react`/`@types`/`esbuild`), not a reported source parse error.
