# 実学習者の入力を待たないテスト方針 v2

目的は機能品質と学習支援品質の自動検証。人間の得点向上・忘却・定着の実証は対象外とし、人間不在を定期テスト全体の停止理由にしない。

## 証拠の種類を分ける

1. 合成入力の機能テスト: 固定の誤答・正答・操作を使い、アプリの実際の結果を検査する。期待値を満たすように作った入力列は学習の証拠ではない。
2. AI模擬学習者の比較: 隔離した実行環境で、支援あり/なしを比較する。実行ログとモデル条件がない場合は「未実施」とする。単独の評価者が両役を演じた文章を、独立した比較実験として報告しない。
3. 人間への実効果: 本プロトコルの評価対象外。上の2種類から自動的に一般化しない。

## 模擬学習者の比較設計

- 同じモデル・設定・制限を使う支援あり/なし条件。符号/対応辺/立式/場合分け/答案形式の弱点profileを事前固定。
- Pre-testで既に正答できた組は「改善」を評価せず、維持・回帰だけを見る。弱点が再現しないprofileは不成立として記録し、成功例へ選び直さない。
- 学習中に与えるのは実アプリから観測した支援。評価基準・正解ファイル・採点実装を学習者側へ渡さない。
- Post/Transferは未見。支援あり条件に与える既学習情報の量・形式を事前固定し、問題ごとの追加ヒントを禁止する。
- 別設定のTransfer問題と近接問題を分離。各profileで最低3組の独立問題対を用意し、実行前に条件・解の完全性を検算する。小標本を母集団へ一般化しない。
- 正誤、最初の方針、途中式、同じミス、支援量、解法の説明を評価する。速さはモデルの応答時間と人間の解答時間を混同しない。
- 独立再実行は再現性の検査であり、数日間の忘却モデルではない。Delayedを実施するなら本当に3〜7日後に実行し、それでも人間の定着とは呼ばない。
- 不明な公式配点・部分点・頻度は推測しない。A/B/C得点目標と問題難度区分を混同しない。

## 毎回の結果

固定ID/問題/入力/期待/実際/証拠/判定を保存。機能PASS/FAILと模擬比較の改善あり/なし/不成立/未実施を分ける。
「支援を受けた模擬学習者は、追加支援なしの未見問題で、支援なし条件より適切な解答行動を示したか」に、実際に実行した比較だけから答える。
